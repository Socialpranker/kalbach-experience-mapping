# Cheatsheet — Mapping Experiences (Kalbach)

## 1. Which Diagram Type?

| Diagram Type | Structure / Axis | Interaction Layer | When to reach for it | Don't confuse with |
|---|---|---|---|---|
| **Alignment Diagram** (umbrella) | Any — chronological / hierarchical / spatial / network | Touchpoints / line of interaction / center line / midpoint (name varies by archetype) | Framing stage, before a specific archetype is picked; goal is shared understanding, not a prescriptive answer | Not itself selectable — once the story's shape is known, switch to the matching archetype below |
| **Customer Journey Map** | Chronological (phases) | Touchpoints | Individual as customer facing a purchase/loyalty decision with one named org | Experience Map — CJM centers on a purchase/loyalty decision with one org |
| **Experience Map** | Chronological (phases) | Touchpoints / physical artifacts | Broad human activity spanning multiple providers or none named; JTBD-level story | CJM (above); Job Map — narrower, one job's 8 universal steps, not a whole domain |
| **Service Blueprint** | Chronological (real-time) | Line of interaction / line of visibility | One specific, real-time service encounter needing diagnosis, timed to the minute | CJM — blueprint is narrow, backstage-heavy; CJM is broad, almost no backstage |
| **Mental Model Diagram** | Hierarchical (towers → mental spaces) | Center line | Person's purpose is broader than your product; expanding what you offer | The chronological archetypes — no stage-1→2 timeline, don't force one on |
| **Spatial Map / Ecosystem Model** | Spatial (position on page = meaning) | Midpoint with arrows | System-level relationships matter more than order; whole job across a wider ecosystem | Experience Map — it keeps a timeline; spatial map drops time for position |

## 2. Decision Rules

- Aspects happen simultaneously, resist one timeline → **hierarchical**, not chronological.
- Need the *shape* → qualitative first; need the *scale* → quantitative after, never to find new themes.
- Layout undecided → default to **table or timeline**; deviate only if the shape itself carries the message.
- Generating → stay **divergent**, ask "how might we...?"; stalled → "what if...?"; switch **convergent** once, deliberately.
- Future vision is simple → band it onto the **current-state map**; separate map only if genuinely complex.
- Have an experience map, need one step's potential → drop into a **job map** — complementary altitude, not a rival.
- Standard blueprint would flatten the emotional driver → add an **expressive** layer, not by default.
- Overview and emotional story both matter → **pair** a spatial map with a chronological diagram.
- New project → sketch a **customer value chain** first (minutes); scale formality to scope × design breadth × group size.

## 3. Tells & Smells

Diagram smells:
- Needs a paragraph to explain itself → fails Self Evidence.
- Scoped to one product/workflow in isolation → fails Holism.
- Single action trace, no feelings/pain points/org roles → fails Multiplicity.
- Emotion curve presented as if measured → almost always an intuitive estimate, not data.
- Grid-lined cells, icon overload, or everything from research dumped in → chartjunk; defeats the single-glance purpose.
- Mental-model boxes name tools/software, not root tasks → kills the longevity a person-focus gives it.
- CJM reads as a touchpoint inventory, no motivations/moments of truth → shows *where*, not *why*.

Process smells:
- Built from a conference room, no field contact → fails Validity; fiction as insight.
- Touchpoint list mirrors the org chart → company-focused, not need-focused.
- Applying empathy without first gaining it → solutions miss real needs.
- Workshop ends with no survey/redistributed diagram/owner checkpoints → alignment evaporates.

## 4. Four-Phase Process

| Phase | Goal | Key Output | Common Failure |
|---|---|---|---|
| **Initiate** | Frame before researching | Value chain, (proto-)personas, diagram type, short proposal | Fixed formality regardless of scope; type picked by label |
| **Investigate** | Ground in evidence: existing → internal → field | Evidence→Interpretations→Implications; draft diagram as hypothesis | Draft workshop drifts into solutioning; internal interviews taken as fact |
| **Illustrate** | Compile findings into one low-noise diagram | Finished diagram via Simplify/Amplify/Clarify/Unify | Research dumped in wholesale; chartjunk; mixed voice |
| **Align** | Turn the diagram into tested decisions | Prioritized concepts (feasibility × value), hypothesis statements, named owners | Diagram presented, not opened; sketches treated as finished specs |

## 5. Seven Principles of Alignment

- **Holism** — frames the person's broader context, not one product?
- **Multiplicity** — several facets layered per side, not a single action trace?
- **Interaction** — an explicit touchpoint layer joins both halves?
- **Visualization** — one graphical overview, not a report that loses impact linearized?
- **Self Evidence** — can someone walk up and orient with no verbal explanation?
- **Relevance** — speaks to a real, known organizational challenge?
- **Validity** — grounded in direct contact with real people, not assumption?
